# bazis-bg 2.3.0

Requires Bazis 2.3 (Django 6.1, FastAPI 0.142) and bazis-author 2.3.

## Fixes

- **Task logs leaked between tasks.** Every task added its log handler to the root logger
  and never removed it: in a handler process the log of a task collected the records of all
  later tasks, and the buffers of finished tasks were never freed. The handler (and the
  level of the root logger) is restored when the task ends.
- **Scheduling.** The scheduler examined only 10 waiting tasks per cycle in an arbitrary
  order (`-id` of UUIDs), so tasks blocked by their limits could keep the others from ever
  starting; and it counted only 10 running tasks, so more tasks than `parallel` allowed
  could run. Waiting tasks are now taken oldest first (100 per cycle) and all running tasks
  are counted; handlers also take the oldest started task first.
- **Cron times** were computed with `datetime.fromtimestamp` in the time zone of the server
  and then interpreted in `TIME_ZONE`: with different zones the tasks ran hours off.
- **Exports split into several workbooks** (more than `limit_rows_split` rows) failed: the
  temporary zip was opened in text mode.
- The cleanup task deletes the files of the deleted tasks from the storage (the raw delete
  left them forever) and never deletes itself.
- `BgBaseLoad` checks that the task has a file before reading it, copies it without loading
  it into memory, and reads only the `.xlsx` files of an archive, also from its folders.
- `set_autocommit` ignored the database alias.
- Unknown cron task classes are logged instead of printed.

## Django 6

- `Meta.index_together` was removed in Django 5.1 and silently ignored, so the model had no
  indexes for the scheduler queries. They are declared as `Meta.indexes`; the migration
  `0005_task_indexes_storage` renames the existing indexes (no rebuild).
- The task file storage is a callable of the field instead of being assigned in `__init__`
  of every instance; changing `BAZIS_STORAGE_BG` needs no migration.

## Other changes

- Dependencies: `bazis>=2.3.0`, `bazis-author>=2.3.0`; `openpyxl`, `psutil` and `crontab`
  get minimum versions instead of `~=` pins (`psutil` 5.9 has no wheels for current Python).
- Tests for the task logs, the export split, the scheduling order and limits, the cron time
  zone and the cleanup.
- CI runs the tests on Python 3.12–3.14 and with the lowest allowed dependency versions;
  releases are made with the Release workflow (see `CLAUDE.md`).
