# bazis-bg 2.5.0

Requires bazis 2.7.0.

## Security

- **The other routes link and include only the tasks the user can see.** The rule of the
  task route (a user sees his own tasks, staff see all) moves from `BgRoute.get_queryset`
  to the classmethod `restrict_queryset(qs, access_action, user=None, **kwargs)` of the
  core `RestrictedQsRouteMixin`, which `BgRoute` now inherits; `get_queryset` applies it.
  As the default route of `bg.Task`, it is what the core of Bazis 2.7 lets the other
  routes link and include: a relationship of another model to a task the user cannot see
  fails with `403 ERR_RELATION_ACCESS` (create, update, the relationships endpoints), and
  `?include=<field>` leaves the task out (the relationship keeps the identifier). Before, a
  model with a foreign key to `bg.Task` linked and included any task, with its arguments,
  log and files.
- `restrict_queryset` never fails without a user: an anonymous user sees no task; a
  missing user is the authenticated user of the request (`UserMixin.CTX_USER_REQUEST`).

## Upgrading a project

- A route set of a model with a foreign key to `bg.Task` needs no checks of its own (the
  sample `entity.Report` and its route set show it).
- A custom route of `bg.Task` that changed the visibility in `get_queryset` changes it in
  `restrict_queryset` and declares `default_route = True`, or the other routes keep the
  rule of `BgRoute`.
